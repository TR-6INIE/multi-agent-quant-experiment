# 基本工作：代码审核与信号时间链追踪

## 1. 相对基线的实际改动
候选代码相对基线的增量改动明确且集中于风险控制（择时退出）分支：
- **新增常量**：`PANIC_BREADTH = 0.40`
- **修改决策逻辑**：将基线的 `if breadth < EXIT_BREADTH:` 修改为 `if breadth < EXIT_BREADTH or breadth_1d < PANIC_BREADTH:`。

其余所有代码（包括breadth平滑计算、entry/exit逻辑、排序、组合构建）与基线完全一致。

## 2. 信号完整时间链与数据时序检查
- **数据时序与未来函数**：`breadths[0]` 即 `breadths[signal_i - 0]`，使用的是模拟决策日当天收盘后的日频数据。`closes` 与 `amounts` 均基于 `signal_i` 截断，无未来函数引入。
- **T+1接口**：执行通过 `SafeStrategyDecision` 交由本地接口统一在次日09:35执行，候选代码未自行实现账户或成交逻辑。
- **异常路径与零交易风险**：`PANIC_BREADTH` 阈值为0.40，远高于极端情况下的 `breadth=0.0`。即使所有股票跌破均线，`valid_t` 判定使得 `b` 下限为0.0，breadth下限为0.0。该路径不会引发除空集外的异常，数据链路安全。
- **跨季度持仓**：当前改动不影响 `_choose_kept` 等持仓维持逻辑，未引入新的跨季度硬编码或隐式持仓依赖。

## 3. 过拟合与狭窄阈值审查（独立必审项）
- **单一区间/单一事件适配风险**：新增的 `breadth_1d < 0.40` 触发条件是一个极端市场异动退出机制。0.40这一阈值在常态市场中极少触发，高度暗示其针对的是特定历史区间内的单日暴跌事件。将该单一事件定制逻辑固化进策略，存在显著的样本内过拟合风险。
- **参数自由度**：实质新增了1个独立参数（`PANIC_BREADTH`）。与原有阈值（0.50, 0.58）形成了新的狭窄阈值带。

## 4. 审核结论
候选代码语法正确，接口符合规范，数据时序无泄漏，未引入阻断级或严重级代码缺陷。但由于存在上述单一事件适配风险，需在绩效工作中进行过拟合验证。

# 绩效工作：创新审计与过拟合验证

## 1. 增量类型判定
**实质机制改进**（具体为择时与风险管理维度的机制增量），非纯参数微调。

## 2. 核心机制与创新证据
- **核心机制**：引入了“非对称恐慌性退出”规则。基线仅依赖3日平滑宽度（`breadth`）跌破0.50作为清仓退出条件，对市场急剧反转的反应存在滞后性。候选代码新增了单日宽度（`breadth_1d`）跌破0.40的硬性触发条件。
- **实质改善判断**：该机制在极端风险情景下将退出条件从“3日平滑确认”改为“单日突破即刻清仓”，构成了状态机层面的非对称转换，属于真实的机制改进而非单纯参数调整。

## 3. 与其他参考策略的新增重合
- **审查结果**：候选代码新增的 `PANIC_BREADTH = 0.40` 逻辑，在提供的机密参考策略（V2、V3.2、Simple_MA）中均未出现。
- V3.2策略虽然也具备日内风险控制与减仓逻辑（`INTRADAY_EXIT_BREADTH = 0.49`），但其基于5分钟级别投影宽度且阈值为0.49，机制与触发条件均与候选代码的日频0.40阈值不同。候选代码未直接照搬其他参考策略。

## 4. 过拟合验证办法与本地量化要求
针对单一区间事件适配风险，提出以下可复算的本地量化验证方法：
1. **触发频率统计**：在本地回测过去5年（如2020-2025）的数据中，统计 `breadth_1d < 0.40` 的纯触发天数。若总触发次数极少（例如<5次），则证明该机制为针对特定极端事件的样本内拟合。
2. **阈值敏感性消融测试**：将 `PANIC_BREADTH` 分别设为 0.35, 0.40, 0.45，对比其在2020-2025年区间的回测净值表现。若 0.40 表现显著优于其他阈值，且其他阈值导致策略表现崩溃或无改善，则确认存在过拟合。
