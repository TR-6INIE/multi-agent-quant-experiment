# 多智能体量化团队实验方案（讨论整理稿）

## 1. 实验目的

本实验研究：将公司人事管理制度引入多智能体量化策略团队后，是否能够提高团队最终产出的量化策略收益。

团队由四个不同的大模型组成，每个模型固定承担一个职位：

1. 策略研究员；
2. 策略工程师；
3. 代码审核员；
4. 数据分析师。

候选模型包括 Qwen、DeepSeek、Kimi 和 GLM，均通过 API 调用。

第一阶段实验中，三个实验组使用完全相同的“模型—职位”匹配关系：

- Qwen：策略研究员；
- DeepSeek：策略工程师；
- GLM：代码审核员；
- Kimi：数据分析师。

第一阶段暂不执行模型—职位轮换实验。第一阶段结论只针对上述固定配置，不直接推广到其他职位分配方式。

### 1.1 2026-08-15方法修订：冻结本地回测全自动闭环

本次重新开始实验，取消人工复制策略到QMT、人工导出结果和`submit-qmt`步骤。代码审核结束后，
管理员程序使用独立冻结Broker自动运行本地回测，并把逐日权益、逐笔成交、每日目标/实际持仓、
期末账户和代码/数据/引擎哈希直接交给数据分析阶段。每轮项目组最多提交3版代码；运行失败只
返回异常信息，不返回中途收益，首个“静态审核通过且本地运行成功”的版本立即冻结，禁止依据
本轮收益继续调参。三版均失败时自动评价本轮未修改基线，并记录交付失败。

候选策略仅接收截至上一交易日的只读、断开底层缓存的历史数组；当日09:35执行价、资金、费用、
整手、T+1和成交只存在于冻结Broker。股票池和申万一级行业仍采用固定当前快照，因此幸存者
偏差与分类前视偏差明确保留并在结果中披露。本文后续关于人工QMT导入、GBK源码和期末持仓
手工重建的旧段落仅作为历史设计记录；当前可执行规则以`管理员/运行指南.md`和
`管理员/config/experiment.json`为准。

### 1.2 2026-08-07方法修订：从零研发改为基线增量改进

由于从零生成策略会使股票池、数据接口、订阅规模和逐bar计算方式过度发散，模型生成的代码
难以在QMT稳定执行。正式实验改为“统一可运行基线上的逐轮增量改进”：

1. 三组第一轮读取完全相同的现有QMT策略，当前使用
   `broad_industry_neutral_momentum_v2.py`；
2. 策略研究员研究基线代码和决策日前外部知识，比较多个改进点，但每轮只选择一个核心改进；
3. 策略工程师只能在基线上做最小修改，不得从零重写或改动无关模块；
4. 代码审核员只把增量改动及其与基线的交互作为本轮阻断对象，不追究基线未修改的既有实现；
5. 第二轮起，每组以上一轮冻结策略作为本组新基线，形成可追溯的演化链；
6. 若候选改进未通过审核，本轮继续部署未修改基线，而不是空仓；
7. 资源约束采用“不得显著增加相对基线负担”的规则，不再用武断的统一股票数或调用数上限。

## 2. 实验评价目标

### 2.1 最终评价指标

三个实验组最终只按照冻结策略在最终样本外期间的收益进行比较。

代码质量、创新性和协作效率不作为实验组胜负的最终指标，因为这些指标难以做到完全客观、统一的量化；但它们仍可作为方法1中个人履职评分和晋升排序的依据。

### 2.2 结论适用范围

本实验最终回答的问题是：

> 在初始资金50万元、禁止杠杆、允许任意集中持仓，并使用相同模型、数据、QMT设置和交易范围的条件下，哪种多智能体协作机制能够产生更高的样本外收益。

由于最终不以回撤、波动率等风险指标决定胜负，本实验结论不能直接表述为“哪个组的策略风险更低”或“哪个组的策略更适合真实资金长期运行”。

## 3. 三组实验设计

### 3.1 方法1：完整人事制度组

方法1包含：

- 四个职位的私有职级；
- 初级、中级、高级三种工作标准；
- 基本工作和绩效工作；
- 每轮个人述职；
- 管理员评价和评分；
- 随机社会因素；
- 根据团队阶段收益确定晋升名额；
- 根据个人最终晋升分确定晋升人员；
- 仅发送给本人的私密评价和晋升结果；
- 下一轮按照新的私有职级要求工作。

每个模型只能知道自己的职级、评价和是否晋升，不得知道其他模型的职级、评价、随机分和晋升结果，也不得知道本轮总晋升名额。

### 3.2 方法2：结构化反思组

方法2用于排除“增加一次反思”本身带来的效果。

方法2包含：

- 与方法1完全相同的模型、职位、任务、数据和QMT结果；
- 每轮结构化工作复盘；
- 任务导向的改进建议；
- 与方法1尽量相近的调用次数、上下文长度和输出结构。

方法2不包含：

- 职级；
- 基本工作与绩效工作的制度性划分；
- 个人绩效分；
- 随机社会分；
- 晋升名额；
- 晋升竞争；
- 与人事制度有关的措辞。

### 3.3 方法3：普通协作组

方法3只保留一般性的职位分工和协作提示词：

- 不设置职级；
- 不进行述职或结构化复盘；
- 不进行个人评分；
- 不提供晋升和人事反馈；
- 每轮收到与其他两组相同的QMT阶段回测结果后，直接开始下一轮正常协作。

方法3的运行目录为：`<WORKSPACE>\方法3`。

### 3.4 三组共同控制条件

三个组必须保持以下条件一致：

- 模型—职位匹配关系；
- API模型具体版本；
- temperature、seed等调用参数（在API支持的情况下）；
- 初始研究任务；
- 可访问的数据和资料范围；
- QMT回测区间和交易设置；
- 每个职位的工具权限；
- 每轮允许的修改次数；
- 每轮策略冻结时间；
- 阶段回测报告的内容和格式。

三组都必须获得相同的季度QMT回测结果。方法1不能因为具有人事制度而额外获得市场信息。

## 4. 五轮时间设计

本实验采用四轮培养与一轮最终评价的顺序模拟实盘设计。

| 轮次 | 本轮开始时允许使用的信息 | 本轮冻结策略的评价期间 | 结果用途 |
|---|---|---|---|
| 第1轮 | 2021-01-01至2024-12-31的开发期信息 | 2025-01-01至2025-03-31 | 三组获得结果；方法1据此进行评价和晋升 |
| 第2轮 | 增加2025年第一季度已经发生的结果 | 2025-04-01至2025-06-30 | 三组获得结果；方法1据此进行评价和晋升 |
| 第3轮 | 增加2025年上半年已经发生的结果 | 2025-07-01至2025-09-30 | 三组获得结果；方法1据此进行评价和晋升 |
| 第4轮 | 增加2025年前三季度已经发生的结果 | 2025-10-01至2025-12-31 | 三组获得结果；方法1进行最后一次评价和晋升 |
| 第5轮 | 增加2025年全年已经发生的结果 | 2026-01-01至2026-06-30 | 最终比较；不再晋升或修改策略 |

### 4.1 严格的时间顺序

每轮必须遵循：

1. 在本轮模拟实盘期开始前完成研究、编码和审核；
2. 冻结本轮策略代码和参数；
3. 冻结后才允许在QMT运行对应的未来区间；
4. 获得结果后才可进入下一轮；
5. 不得使用本轮评价期之后的数据修改本轮策略。

### 4.2 第5轮特殊规则

第5轮策略完成后，三个组的代码和参数同时冻结，再统一回测2026年上半年。

2026年上半年结果可以用于生成最终报告，但不得：

- 再次修改策略；
- 再次进行晋升；
- 选择另一个更有利的参数版本；
- 从多个第五轮候选策略中事后挑选收益最高者。

### 4.3 为什么完整2025年不能作为第五轮最终测试

2025年四个季度已经分别用于推动前四轮策略调整和人事晋升。因此，第五轮策略已经间接使用了2025年全年信息。

可以补充展示第五轮策略对完整2025年的回放结果，但该结果只能作为描述性材料，不能作为三个组最终胜负的依据。

## 5. 收益结果的保存与比较

### 5.1 主要结果

主要结果为三个组第五轮冻结策略在2026-01-01至2026-06-30期间的收益率。

三个组按照完全相同的QMT交易设置运行。最终排名不得根据其他期间的回放结果调整。

### 5.2 辅助结果：模拟实盘累计收益

同时保存各组在整个顺序模拟过程中的累计收益：

```text
第1轮策略运行2025Q1
第2轮策略运行2025Q2
第3轮策略运行2025Q3
第4轮策略运行2025Q4
第5轮策略运行2026H1
```

实验采用资金和持仓连续运行方式，不在季度交界处重置初始资金。每个组从500,000元开始，上一评价区间结束时的现金、持仓、成本和累计盈亏全部带入下一评价区间。

为展示各阶段贡献，可以另外记录每个区间的收益率；下式仅用于核对连续账户收益的复合关系：

```text
模拟期末资产
= 500000
× (1 + 2025Q1收益率)
× (1 + 2025Q2收益率)
× (1 + 2025Q3收益率)
× (1 + 2025Q4收益率)
× (1 + 2026H1收益率)
```

辅助结果反映的是整套协作制度在持续运行过程中的累计赚钱能力；主要结果反映的是经过四轮培养后，第五轮最终策略的样本外表现。

## 6. QMT和交易规则

当前确定的统一设置如下：

- 初始资金：500,000元；
- 允许交易范围：上海证券交易所和深圳证券交易所上市股票；
- 交易制度：T+1；
- 佣金：0.0285%；
- 印花税：0.025%，具体征收方向按照最终QMT配置执行；
- 滑点：0%；
- 行情及成交判断周期：5分钟线；
- 杠杆：禁止；
- 融资融券：禁止；
- 做空：禁止；
- 借款购买证券：禁止；
- 通过衍生品形成超过100%的总风险敞口：禁止；
- 最大持仓数量：不限制；
- 单只股票最大权重：不限制；
- 允许全部资金集中持有一只股票；
- 允许保留任意比例现金；
- 总持仓市值不得超过可用资产；
- 现金余额不得为负。

虽然不限制持仓数量和单只股票权重，但三个组必须使用完全相同的允许交易范围。以下细节仍需在正式实验前统一确定：

- 是否包含ST和*ST股票；
- 是否包含上市时间较短的新股；
- 是否包含创业板、科创板和北交所；
- 是否包含退市整理期股票；
- 停牌、涨跌停和无法成交订单的处理；
- 复权方式；
- 过户费等其他费用是否由QMT自动计入；
- 5分钟线内采用的具体撮合字段和规则，例如信号形成时点、下单时点及成交价，必须保证不使用尚未形成的bar数据。

### 6.1 QMT参考策略的使用规则

现有策略不再仅作为隐藏的平台参考，而是选定其中一份作为三组共同的第一轮基线。研究员、
工程师和审核员均可读取该基线；其他未选中的参考策略仍由管理员保管，仅用于冻结后的机密
增量创新审计。基线相似度本身不构成问题，审计对象是本轮新增部分是否真实、有机制依据，
以及是否直接照搬其他参考策略。

每轮开始时程序把基线复制为`00_baseline_strategy.py`并记录SHA-256。第一轮来源是配置指定
的统一文件，第二轮起来源是本组上一轮`05_strategy_frozen.py`。这样既保留QMT可执行结构，
又能精确追踪每轮究竟改了什么。

中性模板只提供新增代码可采用的平台原语，不得用模板强迫工程师重写基线的未修改模块。
当本轮改进新增或改变数据时点、行情查询、订单状态或T+1路径时，新增部分必须遵守模板；
费用仍只在QMT界面统一设置。研究方案预审不得把模板结构当作改进信号。

## 7. 晋升制度

### 7.1 晋升名额

晋升名额仅适用于方法1，由用户在QMT完成季度回测后按照预先确定的逻辑手工计算并输入实验系统，不需要由实验代码自动计算。

定义：

```text
R_t = 方法1策略在本季度的年化收益率
M_t = 科创50在本季度的年化收益率
P_(t-1) = 方法1策略在上一季度回测中的年化收益率
B_t = max(M_t, P_(t-1))
D_t = R_t - B_t
```

第一轮固定令`P_0 = 0`，因此：

```text
B_1 = max(M_1, 0)
```

这样可以防止2021—2024年开发期的高收益率抬高第一轮baseline。

其中，`B_t`为本季度baseline，`D_t`为本季度策略年化收益率相对baseline的增加量。为消除等于边界时的解释空间，晋升名额统一按以下闭合区间处理：

```text
若 R_t <= 0：0个晋升名额
若 0 < R_t <= B_t：1个晋升名额
若 B_t < R_t < B_t + 5个百分点：2个晋升名额
若 R_t >= B_t + 5个百分点：3个晋升名额
```

这里的“5%”统一解释为年化收益率相差5个百分点，而不是相对baseline增长5%。

市场行情引起晋升名额变化属于本实验所模拟的人事制度环境的一部分。

### 7.2 个人履职评分和随机社会因素

管理员先根据报告和实际工作证据，对四个职位分别进行履职评价。个人履职评分与团队收益分开：团队收益决定晋升名额，个人最终晋升分决定谁获得名额。

正式采用：

```text
最终晋升分 = 管理员履职评分 × 70% + 随机社会评分 × 30%
随机社会评分 ~ Uniform(0, 100)
```

规则如下：

- 每轮预先生成并保存随机种子；
- 每人每轮只能抽取一次随机社会分；
- 不得因为结果不符合预期而重新抽取；
- 随机分只影响晋升排序，不修改管理员原始履职评价；
- 按最终晋升分由高到低分配本轮有限名额；
- 如发生同分，随机社会评分更高者优先晋升；
- 初级只能晋升为中级，中级只能晋升为高级；
- 高级不再晋升，但仍参加履职评价；
- 没有名额时，所有人均不晋升。

70%履职评分和30%随机社会评分的权重作为正式实验规则冻结。

### 7.3 私密反馈

每个模型只接收自己的反馈，建议采用结构化格式：

```json
{
  "round": 2,
  "role": "策略工程师",
  "current_level": "初级",
  "basic_score": 82,
  "performance_score": 74,
  "evidence": [
    "完整实现了研究方案",
    "未充分处理停牌边界条件"
  ],
  "promotion": false,
  "reason_code": "PERFORMANCE_GAP",
  "next_round_requirements": [
    "增加停牌和无可交易标的处理",
    "逐项说明防止未来函数的措施"
  ]
}
```

建议使用以下未晋升原因：

- `QUOTA_LIMIT`：表现达到要求，但本轮名额不足；
- `PERFORMANCE_GAP`：表现未达到晋升要求；
- `INSUFFICIENT_EVIDENCE`：缺少足够的工作证据；
- `ALREADY_TOP_LEVEL`：已经达到最高等级。

本人的私密反馈只注入其下一轮上下文，不进入共享工作目录和其他模型的上下文。

## 8. 通用职级原则

- 所有职位初始均为初级；
- 职级只有本人和管理员可见；
- 高等级自动继承低等级的全部要求；
- 职级改变的是本人工作标准、独立性和严谨程度，不改变四职位的基本分工；
- 高级成员不得直接获得其他职位的职级和评价信息；
- 基本工作用于判断是否合格；
- 绩效工作用于评价主动思考、实质改进和额外贡献；
- 绩效工作不能以破坏上游方案、虚构结果或使用未来数据为代价；
- 所有声称必须有工作产物或具体证据支持。

## 9. 策略研究员职级要求

### 9.1 初级策略研究员

基本工作：

- 针对研究目标检索不少于3项相关资料；
- 记录资料名称、来源、时间和链接；
- 用自己的语言说明资料核心思想；
- 至少比较2个候选策略思路；
- 选择1个思路交给策略工程师；
- 明确股票池、信号公式、调仓频率、持有周期和参数；
- 说明策略的经济逻辑和可能失效场景；
- 主动检查未来数据和幸存者偏差风险。

绩效工作：

- 在已有思路上提出至少1项具有逻辑依据的改进；
- 区分资料原始思路和本人改进；
- 不把单纯修改参数包装成创新。

### 9.2 中级策略研究员

除初级全部要求外，还应：

- 系统比较至少3个候选思路的逻辑、数据需求、实现难度和风险；
- 解释选择和放弃各候选思路的原因；
- 将策略转化为无歧义、可直接实现的规则；
- 明确哪些参数来自资料、哪些参数由团队设定；
- 提出参数敏感性、分阶段表现和失效条件的验证方案；
- 检查策略是否与本地已有策略高度重复。

绩效工作：

- 提出至少1项改变信号机制、风险结构或组合构建方式的实质改进；
- 为改进提出可被回测证伪的假设；
- 保留原始方案和改进方案之间的清晰差异。

### 9.3 高级策略研究员

除中级全部要求外，还应：

- 从经济机制、行为机制或市场结构构建完整研究假设；
- 综合多项资料形成新的策略框架，而非简单拼接指标；
- 说明不同市场环境下可能出现的表现差异；
- 主动减少自由参数，降低数据挖掘风险；
- 设计必要的原始版本、改进版本和消融比较；
- 说明本轮策略与过去方案的继承关系和核心差异；
- 给出判断研究思路无效的停止条件。

绩效工作：

- 形成机制清晰、可实现、可证伪的原创改进；
- 识别团队研究路径可能存在的方向性错误；
- 为下一轮提出研究优先级，但不得使用尚未发生的评价期数据。

## 10. 策略工程师职级要求

### 10.1 初级策略工程师

基本工作：

- 逐项对应研究员给出的策略规则；
- 遵守QMT代码结构和API规则；
- 不得擅自修改选股、交易条件和参数；
- 对参数进行集中配置并添加说明；
- 处理空数据、缺失数据、停牌和无可交易标的等基础异常；
- 标注关键信号使用的数据时间，防止未来函数；
- 输出必要日志；
- 提供“研究规则—代码位置”对应清单；
- 未实际在QMT运行时，不得声称代码已经跑通。

绩效工作：

- 可提出改进建议，但必须与原始实现分开记录；
- 未经确认不得用改进版本替换原始版本；
- 改进建议必须说明理由和风险。

### 10.2 中级策略工程师

除初级全部要求外，还应：

- 合理分离数据获取、信号计算、组合构建和交易执行；
- 系统检查T+1、停牌、涨跌停和重复下单问题；
- 检查股票池成分、财务数据和复权信息的时间有效性；
- 提供代码级检查清单和预期运行流程；
- 对研究方案中的歧义列出采用的解释；
- 对关键参数设置合理边界，避免无约束搜索；
- 提供原始版本和改进版本差异说明。

绩效工作：

- 提出至少1项不改变核心研究逻辑的实质改进；
- 说明改进可能影响的收益来源和风险；
- 不得使用未来评价期结果选择最有利的实现。

### 10.3 高级策略工程师

除中级全部要求外，还应：

- 从数据到下单完整审查时间顺序；
- 设计统一、稳定、可复现的代码结构；
- 识别隐含状态、重复初始化和跨交易日状态污染；
- 控制无意义的参数自由度和复杂度；
- 给出关键参数敏感性验证所需的配置方案；
- 设计安全降级方案，异常时避免错误下单；
- 生成代码版本、prompt版本、参数和依赖信息清单；
- 对研究改进进行技术可行性和过拟合风险评估。

绩效工作：

- 提出能够明显改善稳健性、执行一致性或风险控制的方案；
- 为下游审核提供高质量审计材料；
- 对无法安全实现的要求明确提出风险。

## 11. 代码审核员职级要求

### 11.1 初级代码审核员

基本工作：

- 检查语法、变量、函数调用和QMT API使用；
- 对照研究方案逐项确认是否完整实现；
- 检查明显未来函数和错误数据时间引用；
- 检查T+1、停牌、涨跌停和重复下单问题；
- 将问题划分为阻断、严重、一般和建议四个等级；
- 注明问题位置、原因、影响和修改建议；
- 未在QMT真实运行时，不得声称已经验证跑通。

绩效工作：

- 与冻结的本地策略库比较基本结构；
- 指出可能重复的信号或策略机制；
- 不得仅凭变量名称不同认定创新。

### 11.2 中级代码审核员

除初级全部要求外，还应：

- 追踪关键信号从原始数据到交易决策的完整时间链；
- 检查股票池、指数成分和财务数据是否使用当时可获得的信息；
- 识别过多参数、狭窄阈值和针对单一区间设计的规则；
- 检查研究方案、工程说明和代码之间的一致性；
- 检查边界条件和异常分支；
- 判断问题是否必须退回修改；
- 修改完成后复审并记录问题是否解决。

绩效工作：

- 从核心机制、信号结构和组合方法比较创新性；
- 识别形式创新但实质重复的情况；
- 提出验证过拟合风险的测试建议，但不挑选有利结果。

### 11.3 高级代码审核员

除中级全部要求外，还应：

- 采用对抗性思路寻找隐藏的数据泄漏和不现实假设；
- 审核策略经济逻辑与代码实际行为是否一致；
- 评估策略复杂度是否与可解释收益来源匹配；
- 审核参数敏感性、分阶段稳定性和交易集中风险；
- 检查策略是否逐轮过度适配已经反馈的数据；
- 给出通过、修改后通过或禁止冻结的明确结论；
- 对阻断问题拥有退回工程师修改的权限；
- 维护跨轮审核记录，检查旧问题是否反复出现。

绩效工作：

- 发现其他职位未注意到的系统性风险；
- 对原创性给出基于证据的判断；
- 不因团队需要更高收益而降低审核标准。

## 12. 数据分析师职级要求

### 12.1 初级数据分析师

基本工作：

- 只能根据实际收到的QMT结果分析，不得虚构缺失指标；
- 报告累计收益、年化收益、最大回撤、波动率、夏普、胜率、盈亏比、交易次数和换手率；
- 展示分阶段表现；
- 说明手续费、滑点、T+1等回测假设；
- 区分策略收益、基准收益和超额收益；
- 对无法计算的指标明确说明。

绩效工作：

- 从数据中提出至少1个可能的策略问题或优化方向；
- 优化建议必须与数据现象对应；
- 不得因收益高而忽略严重回撤或收益集中。

### 12.2 中级数据分析师

除初级全部要求外，还应：

- 分析收益是否集中在少数月份、交易或股票；
- 分析回撤发生时间、持续时间和恢复时间；
- 比较不同市场阶段的表现；
- 分析胜率、盈亏比、交易频率与总收益的关系；
- 检查少量异常交易是否主导结果；
- 对上一轮和本轮变化进行归因；
- 区分数据结论与主观推测。

绩效工作：

- 提出具有明确公式和解释的新分析指标；
- 新指标应揭示标准指标没有直接体现的问题；
- 用分析结果提出可验证的下一轮优化假设。

### 12.3 高级数据分析师

除中级全部要求外，还应：

- 分析收益的主要来源及其可持续性；
- 判断性能提升来自真实机制还是少数偶然交易；
- 评估收益、回撤、换手和持仓集中之间的关系；
- 识别策略是否逐轮过度适配已经反馈的数据；
- 比较多轮策略演化路径；
- 为优化建议给出预期影响、风险和可证伪条件；
- 明确哪些问题能由当前数据证明，哪些只能由未来数据检验。

绩效工作：

- 创建具有明确数学定义、经济含义和决策用途的新指标；
- 用多个证据交叉验证优化建议；
- 在第五轮提醒团队冻结代码，禁止利用最终结果继续修改。

## 13. 每轮标准工作流程

除第5轮不再进行晋升外，每轮建议采用以下流程：

```text
冻结本轮基线代码及SHA-256
→ 载入本轮允许使用的信息
→ 策略研究员研究基线与外部知识，提交一个核心增量改进方案
→ 代码审核员进行编程前QMT可实现性预审
→ 最多退回研究员2次；达到上限后，将可由工程师解决的问题转为强制工程清单，只有核心数据
  不可得、内生未来函数、规则矛盾或必须改变研究机制时终止
→ 预审不通过时退回策略研究员提交完整修订方案
→ 预审通过后冻结获批研究方案
→ 策略工程师在基线上最小化实现获批改进
→ 程序执行确定性硬检查，代码审核员对比基线审核增量改动并冻结问题清单
→ 有阻断或严重问题时退回工程师修改
→ 后续审核只复核冻结问题和本次修改引入的回归，不得移动验收标准
→ 审核通过后冻结本轮代码和参数；达到退回上限仍未通过则记录团队未交付
→ 未交付时部署本轮未修改基线，并把收益归属于基线
→ 用户在QMT运行规定的评价区间
→ 导入统一格式的QMT结果
→ 数据分析师生成分析报告
→ 三组分别执行对应的述职、反思或普通流程
→ 方法1由管理员评分并执行晋升
→ 保存本轮完整记录
→ 进入下一轮
```

每轮方案预审最多允许2次退回，三个组使用相同上限；达到2次后仍未通过QMT可实现性预审时，本轮记为方案未通过，不进入编码。方案预审只检查数据、接口、时序、T+1和工程规则能否实现，不评价收益高低。

方案预审通过后，代码审核最多允许3次退回。三个组使用相同上限。第一次审核是唯一一次
全面发现问题的审核，并冻结所有阻断和严重问题编号；后续审核只能关闭原编号，或对比前后
代码后新增由本次修改造成的回归编号。一般问题和建议不得阻止通过。确定性QMT接口、语法、
硬编码未来日期、显式杠杆和T+1基础检查由程序执行，模型不得推翻中性模板中的接口事实。

达到3次退回后仍存在有效阻断或严重问题时，本轮记录为`code_audit_failed`，不再继续修改，
但程序不得以退出码1终止其他组。程序把本轮`00_baseline_strategy.py`复制为冻结部署代码，
继续运行基线并延续真实资金和持仓；收益必须归属于基线，不能归功于被拒绝的候选改进。
本轮未交付事实进入数据分析、述职、复盘和晋升评价。

## 14. 历史模拟中的信息泄漏控制

本实验属于回溯式模拟实盘。由于模型和互联网可能已经包含2025年或2026年的信息，必须尽量控制未来知识：

- 第1轮外部资料发布日期不得晚于2024-12-31；
- 后续各轮只能新增该轮决策日之前发布的资料；
- 每份资料必须记录标题、来源、发布日期和链接；
- 禁止使用未来市场总结、年度涨幅榜和事后复盘；
- 禁止把后续已知赢家、热门行业或个股表现作为选股理由；
- prompt必须写明当前模拟决策日期和允许使用的信息截止日期；
- QMT数据调用必须遵守当时可得原则，特别注意财务公告日期和指数成分日期。

仅依靠prompt无法彻底清除模型训练数据中的未来知识。因此，正式结论应注明这是回溯式模拟实验；如需更强证据，应在实验完成后继续进行真正尚未发生行情的前瞻测试。
