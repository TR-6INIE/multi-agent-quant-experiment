# 三组实验自动本地回测运行指南

本版实验不再把策略复制到QMT，也不再人工填写或导入QMT结果。一次`prepare-round`会完成
研究、方案预审、工程实现、代码审核、冻结本地回测、结果归档和数据分析。

## 1. 固定实验设置

- 三组角色与模型保持不变：Qwen策略研究员、DeepSeek策略工程师、GLM代码审核员、
  Kimi数据分析师。
- 第一轮每组初始现金50万元；以后直接恢复本组上一轮期末现金、持仓、成本和策略选中状态。
- 冻结撮合引擎统一处理整手、现金、持仓、T+1、佣金0.0285%、印花税0.025%和最低佣金5元。
- 日线策略只接收截至上一交易日的日线数据；固定时点策略可声明1分钟
  或5分钟已完成信号K线，并在严格更晚的K线上成交。
- 原生一分钟策略逐根接收已经完整收盘的当前一分钟OHLCVA，同时保留截至上一交易日的
  日线历史和固定行业信息，可在一天内多次买卖；其订单
  只能在下一根全市场一分钟K线开盘处理。成交价格始终只在冻结Broker内。
- 股票池和申万一级行业使用固定当前快照。此项按实验决定不再修改，因此结果保留幸存者偏差
  与分类前视偏差；每份回测结果都会披露，不能宣称是完全无偏历史回测。
- 开发回测固定评分区间为2022-01-01至2024-12-31；缓存额外保留2020-04-01起的
  行情作为预热历史，但预热期不计入开发绩效。
- 五轮盲测评价区间仍为2025年四个季度及2026年上半年。候选冻结并记录哈希后才运行
  对应评价区间一次；评价结果不会返回同轮修改。

本地回测配置位于`管理员/config/experiment.json`，核心外部文件为：

```text

```

## 3. 启动一轮

在Jupyter Notebook中：

```python
%run "<WORKSPACE>/管理员/run_all.py" prepare-round --round 1
```

或在PowerShell中：

```powershell
python .\管理员\run_all.py prepare-round --round 1
```

同一轮命令可以安全重跑。程序会跳过已经处于`complete`或`awaiting_evaluation`的组；如果某组已完成冻结盲测、但在数据分析或轮后处理阶段中断并处于`backtest_complete`，则直接复用已保存的冻结策略、回测结果和合格的分析响应，只补做尚未完成的轮后步骤，不会重新研究、改写策略或运行盲测。

程序依次处理方法1、方法2、方法3。每组自动执行：

1. 第一轮复制统一的无交易逻辑接口骨架；第二轮起使用本组上一轮冻结策略作为参考。
2. Qwen根据决策日前公开资料自主研究候选；提示词不列举策略方向，每轮只交付一个完整方案。
   策略可以只用行情，也可以在`data_spec['fundamental_fields']`中声明最多8个财务字段。
   字段目录只是接口能力说明，不是候选策略推荐。日频和分钟策略收到的财务横截面统一截止到
   当前策略日的上一交易日，并附带报告期、公告可得日期和截止日期；候选代码不能直接读取缓存，
   缺失财务值为NaN。
3. GLM做编程前可实现性预审，最多退回研究方案2次。
4. DeepSeek按`SafeStrategyContext`接口提交完整UTF-8策略。
5. 程序做语法和安全边界检查，GLM审核完整候选方案和代码。
6. 每轮项目组最多提交3版代码。语法、审核、运行错误修复和开发期改进共用这3版上限。
7. 静态审核通过后只运行2022—2024开发回测。开发结果会交给Qwen；它可以选择接受并冻结候选、
   提出一组保持获批核心假设和安全接口不变的有限修改，或在候选触发预先声明的停止/失效条件时
   选择`REJECT`。`REJECT`会放弃本轮候选并使用本轮开始时的未修改基线进行盲测，不把结果归因
   给被拒绝的改进；`FREEZE`只表示候选满足研究接受条件并应进入盲测。
8. 选定候选后先冻结代码并记录哈希，再单次运行本轮2025季度（第五轮为2026上半年）盲测。
   当轮研究、工程和代码审核阶段看不到任何评价指标；评价运行后不再允许修改候选。
9. 三版都失败时记录`code_audit_failed`：第一轮用空策略骨架保持现金，之后用上一轮冻结策略继续运行。
   若候选开发期通过但冻结后在评价数据上发生运行错误，记录`evaluation_runtime_failed`并回退基线，
   不把错误或评价数据返回同轮重新开发。
10. 程序分别归档开发缓存、评价缓存、策略和引擎哈希，以及逐日权益、逐笔成交、每日状态和期末组合。
11. Kimi自动完成数据分析；方法2再完成私人结构化复盘，方法3直接完成。
    方法1生成私人述职和管理员评价材料，状态为`awaiting_evaluation`。

三组在每一轮收到完全相同的技术工作要求。工作要求以方法1在该轮开始时各角色的实际职级
为准；例如方法1审核员上一轮晋升为中级，则下一轮三个方法的审核员都执行累计到中级的
基本工作和绩效工作。方法2和方法3看不到职级名称。方法1角色的私人目标是争取晋升；
方法2和方法3角色的目标是帮助团队找到未知评价期表现良好且风险可接受的策略。方法1上一轮
未完成管理员评价时，程序禁止方法2和方法3进入下一轮，防止工作要求错位。

数据分析输入会附带管理员确认的部署归属。若本轮候选被否决或未交付而采用
`reuse_baseline`，盲测结果必须归属于本轮开始时未修改的基线；开发候选与冻结盲测代码
哈希不同是预期结果，不得据此声称候选已经部署或发生版本错配。

候选代码可以选择两种日内接口：固定时点模式继续通过`data_spec`声明周期和时点，每日至多
调仓一次；原生分钟模式设置`engine_mode='minute'`并实现`on_minute(context)`，可以在一天
内多次产生订单。每根分钟K线最多提交50个不同股票订单，成交量不得超过该股票下一分钟
市场成交量的10%。同一根K线看信号并成交会被拒绝。原始K线读取地址为
`datadir/SH|SZ/60|300|86400/证券代码.DAT`。候选代码不得导入文件系统、网络、进程模块，不得调用`open/load/getattr`，不得读取完整缓存
或私有属性，也不得自行实现账户、撮合、费用和T+1。程序传入的历史数组是断开底层缓存的
只读副本，并且严格结束于上一交易日。

区间时，不能把结果表述为完全精确的历史成交复现。

## 5. 方法1评分与晋升

方法1每个非最终轮完成后查看：

```text
方法1/runs/round_XX/admin/manager_packet.md
方法1/runs/round_XX/admin/manager_evaluation_template.json
```

填入0—100分履职评分及证据评语，再按预先确定的收益规则决定晋升名额：

```powershell
python .\方法1\run.py apply-evaluation --round 1 `
  --file '.\方法1第1轮评价.json' --promotion-slots 2
```

最终晋升分仍为履职评分70%加预先生成的随机社会评分30%；同分时随机分高者优先。
第5轮为最终评价轮，不再执行晋升。

方法1完成评价，且三组当前轮都为`complete`后：


依次将轮次改为3、4、5。不得删除或手工修改活动中的`experiment_state.json`、冻结策略、
审核报告、哈希清单或本地回测输出。
